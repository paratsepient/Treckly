# Інструкція для ведучого сесії

Прототип «Щоденні замовлення за Попереднім переліком». Усі дані синтетичні, СЕДО імітується (номер вводять вручну).
Працює на цьому ПК без інтернету.

## Запуск

Один раз після отримання коду:

```bash
pnpm install
pnpm build
```

Щоразу перед сесією:

```bash
pnpm start
```

Відкрийте **http://localhost:4340/** у Chrome або Edge. Зупинка — `Ctrl+C` у вікні терміналу.

- Відкривайте прототип **в одній вкладці**. База даних живе в браузері й має одного власника; друга вкладка покаже
  повідомлення «Демо вже відкрите в іншій вкладці».
- Дані зберігаються в цьому браузері між запусками. Перед кожним учасником натискайте **Демо → Заповнити прикладами** (демо-стан нижче) або **Демо → Скинути демо** (порожня база без жодного рапорту):
  стан повернеться до початкового (11 заявок у різних станах, дата 15 лютого 2027).
- Якщо щось пішло не так, на стартовому екрані є кнопка «Скинути локальні дані й повторити».

## Демо-середовище

Кнопка **Демо** у верхній смузі кожного екрана відкриває екран «Демо-середовище» (`#/demo`):

- угорі — **Дата демо** з кнопкою **Наступний день** (дата +1 і нагадування тим, у кого є заявки), **Тема** (світла/темна)
  і **Скинути демо**;
- нижче — **Оберіть роль**: ролі розставлено за структурою, від Відділу оборонних ресурсів і Голови (рівень 5)
  через напрямок, РУ й бригади до в/ч (рівень 1). Поточну роль позначено. Натиск на картку перемикає роль без паролів
  і відкриває її початковий екран. Адміністратор — окремо, «поза маршрутом».

Угорі кожного екрана — позначка «Демонстраційні дані, СЕДО імітується», поточна демо-дата і роль.

## Ролі й що перевіряє кожна

«Запланований перелік» є в меню кожного уповноваженого й керівника: в/ч, бригада й РУ бачать план своїх в/ч, напрямок, Відділ і Голова — увесь перелік напрямку.

| Роль у демо-середовищі | Екрани | Що робить |
| --- | --- | --- |
| Автор заявок (в/ч А0001 / А0002 / А0003) | Моє майно, Нова заявка, Мої заявки, Витяги по в/ч, Сповіщення | Створює заявку (за переліком і із заміною) лише з позицій, запланованих на його в/ч («Моє майно → Заплановано»), бачить перевірки й бюджет, подає, стежить за треком, виправляє повернуту, відкликає |
| Уповноважений заступник командира рівня 1–4 | Черга рівня, Реєстр і зведення, Сповіщення | Обирає заявки, формує денний перелік, повертає заявку з приміткою, розформовує перелік |
| Командир / начальник / заступник Голови рівня 1–4 | Денний перелік, Реєстр і зведення, Сповіщення | Погоджує перелік із числовим номером СЕДО |
| Відділ оборонних ресурсів (рівень 5) | Черга рівня, Затверджені закупівлі, Закупівлі й видача, Запланований перелік, Реєстр | Формує остаточний перелік, переглядає, друкує або завантажує його в Word, несе на підпис Голові й відмічає «Підписано Головою» з номером СЕДО: бюджет резервується, витяги по в/ч формуються; якщо не підписав — «Голова не підписав…» з приміткою, заявки повертаються авторам. Після витягу — «Закупівлі й видача»: підтверджує закупівлю документом приймання, видає нове актом або закриває як не виконано |
| Голова (рівень 5) | Запланований перелік, Реєстр і зведення, Затверджені закупівлі | Лише моніторинг: перелік підписує на папері, у системі погодження не має |
| Демо-адміністратор | Користувачі, Реєстр і зведення, ТВО, Журнал дій | Налаштовує людей (ПІБ, посада, відділ, доступні КЕКВ), призначає й знімає ТВО, дивиться зведення й журнал |

## Сценарії для сесій

1. **Автор: заявка із заміною.** Автор в/ч А0001 → «Нова заявка» → «Додати рядок» → тип «Заміна» → позиція
   «Антена всеспрямована 2,4 ГГц» → замінити на «Антенна система мобільна». Праворуч видно вплив на бюджет:
   новий КЕКВ витрачається, старий не змінюється. «Подати» → номер рапорту в СЕДО (будь-яке число, напр. 5310042) → у «Моїх заявках» заявка на рівні 1 з цим номером.
2. **Автоперевірки.** Спробуйте кількість більшу за доступну або позицію «Квадрокоптер розвідувальний» (перевищує
   залишок КЕКВ 3110): помилка видна біля рядка, «Подати» заблоковано.
3. **Рівень 1: вибір і перелік.** Уповноважений в/ч А0001 → «Черга рівня» → обрати частину заявок → «Сформувати
   перелік». Необрані лишаються. Керівник → «Денний перелік» → «Погодити» з номером СЕДО (літери відхиляються).
4. **Повернення.** Уповноважений рівня 3 → «Повернути…» у заявці ЗМ-0003 → примітка обов'язкова. Автор в/ч А0002
   бачить сповіщення з приміткою, рівні 1–2 теж; автор прибирає зайвий рядок і подає нову версію: вона йде з рівня 1.
5. **Розформування й «Наступний день».** Уповноважений рівня 1 розформовує перелік і формує знову; «Демо → Наступний день»:
   у «Сповіщеннях» з'являються нагадування з лічильником днів.
6. **Відкликання.** Автор в/ч А0003 відкликає ЗМ-0006 (рівень 4). Затверджену заявку відкликати не можна.
7. **Затвердження.** Відділ формує перелік із ЗМ-0007, Голова «Затвердити». «Затверджені закупівлі» і «Витяги по в/ч»:
   рядок заміни стає «Заміна погоджена», у «Реєстрі і зведенні» змінилися бюджет і показники. Експорт: «Друк / PDF»
   (у вікні друку оберіть «Зберегти як PDF») або «Word (.docx)».

## Для розробників

- `pnpm check` — типи й тести всіх пакетів; `pnpm test:e2e` — сценарії E1–E7 і доступність у Chrome (потрібна збірка `pnpm build`).
- Прототип не підключається до СЕДО й не містить реальних даних.
